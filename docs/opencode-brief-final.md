# بریف کامل پروژه - اپ مشاور هوشمند کارهای روزانه

## چیستی اپ (مهم‌ترین اصل طراحی)
این اپ یک لیست کار ساده نیست. اپ نقش **فرمانده** را دارد: به کاربر می‌گوید دقیقاً چه زمانی
چه کاری انجام بدهد و یادآوری می‌کند. کاربر هم کارهای یک‌باره (Task) دارد و هم
اهداف بلندمدت و ادامه‌دار (Goal) مثل «یادگیری زبان» یا «تمرین ویولن» که هر بار
رویشان کار می‌کند، آن جلسه را ثبت (Log) می‌کند.

## استک فنی (قطعی)
- Next.js (App Router) + TypeScript، همه‌چیز یکپارچه (بدون Express جدا)
- Server Actions به‌جای REST API جدا
- Prisma نسخه‌ی ۶.x (نه ۷) + Prisma Postgres — schema کامل در `prisma/schema.prisma` پیوست شده
- احراز هویت: **Auth.js (NextAuth v5)**، credentials (ایمیل/رمز) + Google provider
  (فرض بر این است چون دکمه‌ی گوگل در طراحی هست؛ اگر ترجیح دیگری هست قبل از شروع بگو)
- خروجی نهایی: اپ وب روی Vercel + پوشش با **Capacitor** برای گرفتن APK اندروید
- نوتیف فاز اول: **Local Notification** با `@capacitor/local-notifications`،
  زمان‌بندی‌شده بر اساس فیلد `reminderTime`/`reminderDays` در جدول Goal و ددلاین Task.
  نوتیف پویا (مبتنی بر رفتار واقعی کاربر + Push از سرور) فاز بعد است، الان نساز.
- زبان رابط: فارسی، جهت RTL، فونت Vazirmatn (Google Fonts)

## طراحی - مرجع‌ها
دو فایل HTML پیوست شده‌اند؛ هر دو فقط **مرجع بصری** هستند (نه کد نهایی):
- `design-reference-main.html`: سؤال‌های آنبوردینگ، نتیجه‌ی پرسونا، اهداف، نوتیف، پروفایل
- `design-reference-login-theme.html`: صفحه‌ی ورود و بخش تنظیم تم

### سیستم رنگ (CSS Variables - این ساختار باید دقیقاً حفظ شود)
```
--bg:      پس‌زمینه‌ی اصلی (پیش‌فرض #0B0E13 در حالت تیره)
--surface: کارت‌ها
--raised:  عناصر روی کارت (نوار پیشرفت و غیره)
--line:    خطوط و بوردر
--text:    متن اصلی
--muted:   متن کم‌رنگ
--accent:  رنگ تأکید — این یکی توسط کاربر قابل‌تغییر است (از پروفایل)
--ink:     متن روی رنگ تأکید
--warn:    هشدار / یادآوری زمان
```
فونت: Vazirmatn. حس کلی: تیره، جدی، کم‌حواس‌پرتی، رنگ تأکید فقط جای تصمیم اصلی.

### تم قابل‌تغییر توسط کاربر
- کاربر از پروفایل رنگ `--accent` را آزادانه انتخاب می‌کند (چند رنگ پیشنهادی + رنگ‌یاب آزاد)
- کاربر فقط بین دو **حالت نمایش** (`dark` / `light`) سوییچ می‌کند؛ بقیه‌ی رنگ‌ها
  (پس‌زمینه، متن) بر اساس این دو حالت از پیش تعریف‌شده‌اند تا خوانایی همیشه تضمین شود
- مقادیر در `User.themeAccent` و `User.themeMode` ذخیره می‌شوند (در schema هست)
- این دو مقدار باید به‌صورت CSS variable در ریشه‌ی صفحه inject شوند تا کل اپ را عوض کنند

## پرسوناها و لحن (نکته‌ی مهم)
- ۴ تا ۶ پرسونا داریم که در یک فایل `personas.json` تعریف می‌شوند (نه در دیتابیس)
- هر پرسونا یک `toneStyle` دارد: `"commander"` (دستوری، مثل «بلند شو، وقتشه»)
  یا `"gentle"` (ملایم، بدون قضاوت). **این یکسان نیست**: پرسونای حساس به شرم/فشار
  باید لحن ملایم بگیرد، پرسونای انگیزه‌ی بیرونی/بهره‌ور زیر فشار لحن فرمانده‌وار
- فعلاً محتوای دقیق پرسوناها و جملات لیلا نداریم؛ با ۴ تا ۶ پرسونای placeholder
  (می‌توانی خودت بسازی) شروع کن، بعداً جایگزین می‌شود
- جملات انگیزشی نوتیف در فایل `motivational-lines.json` می‌آیند، دسته‌بندی‌شده بر اساس
  `toneStyle` و نوع رویداد (`before_task`, `after_missed_day`, `streak`, `goal_reminder`)

## مسیر کاربر (به ترتیب بساز، هر مرحله یک برش کامل با API + UI)
0. **auth**: صفحه‌ی ورود/ثبت‌نام طبق مرجع طراحی (موج بالا + فرم)
1. **آنبوردینگ**: ۶ تا ۸ سؤال یکی‌یکی با نوار پیشرفت، از `personas.json`
2. **نتیجه‌ی پرسونا**: محاسبه‌ی ساده (rule-based، نه ML) و نمایش گروه + ذخیره در `User.personaId`
3. **اهداف (Goals)**: افزودن هدف با عنوان، هدف هفتگی (دقیقه یا روز)، ساعت یادآوری.
   هر هدف با کلیک، صفحه‌ی جزئیات باز می‌شود: لیست GoalLog ها (چند دقیقه، چه بخشی)
   + فرم ساده‌ی افزودن لاگ جدید (دقیقه + یادداشت کوتاه). زیاد شلوغ نشود.
4. **تسک‌های روزانه**: ساخت/تکمیل/تعویق/شکستن تسک (از schema قبلی)
5. **نوتیف (Local Notification)**: زمان‌بندی بر اساس Goal.reminderTime/reminderDays
   و Task.deadline، با متن از `motivational-lines.json` طبق `toneStyle` پرسونای کاربر
6. **داشبورد هفتگی**: جمع GoalLog های هفته‌ی جاری به ازای هر هدف، درصد پیشرفت
   نسبت به targetMinutesPerWeek/targetDaysPerWeek
7. **پروفایل**: اطلاعات کاربر، گروه فعلی، آمار ساده، و بخش تنظیم تم (بالا توضیح داده شد)

## ثبت رویداد (الزامی برای هر اکشن کاربر)
فایل `lib/track.ts` را اول از همه بساز:
```ts
import { prisma } from "@/lib/prisma";

export async function track(
  userId: string,
  eventType: string,
  metadata?: Record<string, unknown>,
  taskId?: string,
  goalId?: string
) {
  try {
    await prisma.event.create({ data: { userId, eventType, taskId, goalId, metadata: metadata as any } });
  } catch (err) {
    console.error("track failed:", err); // هرگز نباید اپ را خراب کند
  }
}
```
هر اکشن کاربر (پاسخ به سؤال، تکمیل تسک، تعویق، ثبت GoalLog، باز/نادیده‌گرفتن نوتیف)
باید این تابع را صدا بزند.

## چیزی که فعلاً نمی‌خواهیم (مهم، وقت روی این‌ها نگذار)
- ML یا خوشه‌بندی واقعی (فاز ۲ پروژه، بعداً)
- نوتیف Push پویا و سرور همیشه‌روشن (فاز ۳ پروژه، بعداً)
- طراحی نهایی پولیش‌شده (توکن‌های رنگ فعلی کافی‌اند)
- مشاور AI (در آینده اضافه می‌شود، فقط مطمئن شو Event و GoalLog تمیز و ساختاریافته ثبت می‌شوند تا بعداً قابل‌استفاده باشند)
